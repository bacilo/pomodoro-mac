<task type="auto">
  <name>Task 1: Add universal binary build and expand CI verification</name>
  <files>.github/workflows/release.yml</files>
  <action>
Modify the existing release workflow in three places:

1. **Build step** ("Build app (Release configuration)"): Add two build settings to the existing xcodebuild command:
   - `ARCHS="x86_64 arm64"` — build for both Intel and Apple Silicon
   - `ONLY_ACTIVE_ARCH=NO` — ensure both architectures are built, not just the runner's native arch

   These go as additional lines after `CURRENT_PROJECT_VERSION=${{ github.run_number }}` in the existing build command.

2. **Ad-hoc signing step**: Rename from "Ad-hoc code sign for Apple Silicon" to "Ad-hoc code sign" (it now signs a universal binary, not just Apple Silicon). The codesign command itself stays the same (`codesign --force --deep --sign -`).

3. **Verify step** ("Verify build"): Expand to add two new checks AFTER the existing version check:

   a. **Architecture verification** — Add after the version match check:
   ```bash
   # Check universal binary (Intel + Apple Silicon)
   ARCHS=$(lipo -info "$APP_PATH/Contents/MacOS/PomodoroApp" 2>&1)
   echo "Architectures: $ARCHS"

   if ! echo "$ARCHS" | grep -q "x86_64"; then
     echo "Missing x86_64 (Intel) architecture"
     exit 1
   fi

   if ! echo "$ARCHS" | grep -q "arm64"; then
     echo "Missing arm64 (Apple Silicon) architecture"
     exit 1
   fi

   echo "Universal binary verified (x86_64 + arm64)"
   ```

   b. **Code signing verification** — Add after the architecture check:
   ```bash
   # Verify ad-hoc code signature
   if ! codesign --verify --deep --strict "$APP_PATH" 2>&1; then
     echo "Code signature verification failed"
     exit 1
   fi

   echo "Code signature verified"
   ```

   c. Update the final success message to: `echo "Build verification passed: version, architecture, and signing OK"`

Do NOT change any other steps (checkout, version extraction, tests, packaging, checksum, release creation). The trigger, runner, permissions, and release notes all stay exactly the same.
  </action>

- `lipo -info` in the verify step
- `codesign --verify --deep --strict` in the verify step

<task type="auto">
  <name>Task 2: Local validation of universal build and verification</name>
  <files>.github/workflows/release.yml</files>
  <action>
Validate the workflow changes by running the equivalent commands locally:

1. **Build with universal architecture settings:**
   ```bash
   xcodebuild build \
     -project PomodoroApp.xcodeproj \
     -scheme PomodoroApp \
     -configuration Release \
     -derivedDataPath build/ \
     -destination 'platform=macOS' \
     CODE_SIGN_IDENTITY="-" \
     CODE_SIGNING_REQUIRED=NO \
     CODE_SIGNING_ALLOWED=NO \
     MARKETING_VERSION=99.99.99 \
     CURRENT_PROJECT_VERSION=1 \
     ARCHS="x86_64 arm64" \
     ONLY_ACTIVE_ARCH=NO
   ```

2. **Ad-hoc sign:**
   ```bash
   codesign --force --deep --sign - build/Build/Products/Release/PomodoroApp.app
   ```

3. **Verify architecture (must show both x86_64 and arm64):**
   ```bash
   lipo -info build/Build/Products/Release/PomodoroApp.app/Contents/MacOS/PomodoroApp
   ```

4. **Verify code signing:**
   ```bash
   codesign --verify --deep --strict build/Build/Products/Release/PomodoroApp.app
   ```

5. **Clean up build directory:**
   ```bash
   rm -rf build/
   ```

If any step fails, diagnose and fix the workflow file before proceeding. The most likely failure point is step 1 — if the runner/machine cannot cross-compile for x86_64, the build will fail. In that case, check whether Xcode SDK support is available.
