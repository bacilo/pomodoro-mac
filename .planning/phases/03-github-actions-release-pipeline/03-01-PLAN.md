<task type="auto">
  <name>Task 1: Create GitHub Actions release workflow</name>
  <files>.github/workflows/release.yml</files>
  <action>
Create `.github/workflows/release.yml` with a single job `build-and-release` that runs on `macos-latest` with `permissions: contents: write`.

The workflow triggers on `push.tags` matching `v*`.

Steps in order:

1. **Checkout** — `actions/checkout@v6`

2. **Extract version from tag** — Use bash parameter expansion `VERSION=${GITHUB_REF#refs/tags/v}` and write to `$GITHUB_ENV`. Echo the version for logging.

3. **Run tests** — Execute `xcodebuild test -project PomodoroApp.xcodeproj -scheme PomodoroApp -destination 'platform=macOS'`. This gates the entire release: if tests fail, nothing else runs. (Satisfies test-first requirement from CLAUDE.md.)

4. **Set version from tag** — Pass version to xcodebuild as build setting override in the build step itself (MARKETING_VERSION and CURRENT_PROJECT_VERSION). Do NOT use agvtool or PlistBuddy to modify project files — instead pass `MARKETING_VERSION=${{ env.VERSION }}` and `CURRENT_PROJECT_VERSION=${{ github.run_number }}` directly to xcodebuild as command-line build setting overrides. Command-line build settings override project.pbxproj values without modifying files. This is cleaner than modifying project.pbxproj in CI. (Satisfies VERS-01, VERS-02, VERS-03.)

5. **Build app (Release configuration)** — Single xcodebuild command:
   ```
   xcodebuild build \
     -project PomodoroApp.xcodeproj \
     -scheme PomodoroApp \
     -configuration Release \
     -derivedDataPath build/ \
     -destination 'platform=macOS' \
     CODE_SIGN_IDENTITY="-" \
     CODE_SIGNING_REQUIRED=NO \
     CODE_SIGNING_ALLOWED=NO \
     MARKETING_VERSION=${{ env.VERSION }} \
     CURRENT_PROJECT_VERSION=${{ github.run_number }}
   ```
   (Satisfies BUILD-02, VERS-02, VERS-03.)

6. **Ad-hoc code sign** — `codesign --force --deep --sign - build/Build/Products/Release/PomodoroApp.app` (required for Apple Silicon compatibility).

7. **Verify build** — Check .app exists and verify CFBundleShortVersionString matches expected version using PlistBuddy on the built Info.plist (`build/Build/Products/Release/PomodoroApp.app/Contents/Info.plist`). Fail the workflow if version mismatch.

8. **Create distribution zip** — Use `ditto -c -k --keepParent --sequesterRsrc build/Build/Products/Release/PomodoroApp.app PomodoroApp-v${{ env.VERSION }}.zip`. Do NOT use `zip -r` (loses macOS metadata, causes "damaged app" errors). (Satisfies BUILD-03.)

9. **Generate SHA256 checksum** — `shasum -a 256 PomodoroApp-v${{ env.VERSION }}.zip > checksums.txt`. (Satisfies BUILD-05.)

10. **Create GitHub Release** — Use `ncipollo/release-action@v1` with:
    - `artifacts`: glob matching `PomodoroApp-v*.zip` and `checksums.txt`
    - `body`: Markdown with installation instructions including macOS 15.1+ Sequoia xattr workaround and checksum verification command
    - `draft: false`
    - `prerelease`: detect from tag name containing "beta" or "alpha"
    - `generateReleaseNotes: true` for auto-generated changelog from commits
    (Satisfies BUILD-04.)

Important notes:
- Use `macos-latest` runner (not pinned, per research recommendation to start with auto-updates)
- The `permissions: contents: write` is REQUIRED at job level or workflow level — without it, release creation fails with 403
- The release body should include clear installation steps: download, extract, move to /Applications, right-click Open
- Include Sequoia 15.1+ specific instructions: `xattr -r -d com.apple.quarantine` command and System Settings path

   ```bash
     -destination 'platform=macOS' \

     CODE_SIGNING_REQUIRED=NO \
     CODE_SIGNING_ALLOWED=NO \
     MARKETING_VERSION=99.99.99 \
     CURRENT_PROJECT_VERSION=999
   ```
   Then verify the version was injected:
   ```bash
   /usr/libexec/PlistBuddy -c 'Print :CFBundleShortVersionString' \
     /tmp/pomodoro-ci-test/Build/Products/Release/PomodoroApp.app/Contents/Info.plist
   ```
   Expected: `99.99.99`. If this does NOT output `99.99.99`, the MARKETING_VERSION override approach does not work and the workflow needs to be updated to use `agvtool new-marketing-version` or `sed` on project.pbxproj instead. Update the workflow accordingly if needed.

   ```bash
     /tmp/pomodoro-ci-test/Build/Products/Release/PomodoroApp.app

   ```
   Expected: no error output (exit code 0).
